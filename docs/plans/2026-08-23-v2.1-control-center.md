# Assignmark 2.1 Control Center Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Replace the calendar-only Hide/Dim/Clear button stack with an accessible, compact control center that reports current-view progress, filters All/Pending/Done, clears only an explicit scope, and supports one-level undo without adding permissions or weakening persistence.

**Architecture:** Keep canonical identity and serialized extension storage in `src/core.js`. Add pure filter/progress logic in a new `src/control-center.js`, then render it from `src/content.js` through callbacks rather than letting UI code mutate storage directly. Treat rendered IDs as the current-view scope; deduplicate repeated DOM instances of the same canonical assignment. Preserve legacy `hide`/`dim` settings and map existing `hide: true` users to the Pending filter on first 2.1 normalization.

**Tech Stack:** Manifest V3, JavaScript ES modules bundled by esbuild, `chrome.storage.local`, Node 20 test runner, jsdom, headless Chromium/CDP fixture verification.

---

## Product boundaries

- No new Chrome permissions, host matches, background worker, network calls, remote code, analytics, or Schoology credentials.
- “Done” remains a private personal checkoff; it must not imply Schoology submission, grading, or official completion.
- Progress means unique assignments/events currently rendered in the active Schoology view, not the entire account.
- Only explicit user actions may remove checked state. Filtering, rerendering, navigation, and resolver upgrades are never deletion paths.
- Version 2.1 remains calendar-only. Cross-surface injection begins only after separate fixtures and selector evidence exist.

## Release roadmap

- **2.1.0 — Control Center:** progress, All/Pending/Done filters, scoped clear, one-level undo, accessible compact UI.
- **2.2.0 — Recovery and Diagnostics:** validated export/import, privacy-safe diagnostics, manual rescan, appearance/position preferences.
- **3.0.0 — Schoology-wide adapters:** calendar, Upcoming, course-material, and assignment-list adapters sharing canonical state, each gated by fixtures and runtime tests.

## 2.1 acceptance gate

- Existing v1.2 and 2.0 checked states survive upgrade.
- The same assignment remains checked across rerenders and reloads.
- Progress deduplicates repeated DOM instances by stable ID.
- Filtering never writes or deletes checkbox state.
- Clear View affects only unique currently rendered IDs.
- Clear All is separately labeled, counted, confirmed, and undoable.
- Undo restores persisted timestamps and survives reload.
- No new permissions, hosts, network requests, background worker, or remote code.
- Unit tests, dependency audit, production build, ZIP integrity, and clean-profile Chromium runtime probe pass.
- README, privacy guidance, manifest, and runtime behavior remain consistent.
