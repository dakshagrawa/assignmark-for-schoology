# Assignmark 2.2.1 Customizable Controls Implementation Plan

> **For Hermes:** Execute this plan on `fix/v2.2.1-v20-button-sizing`; merge only through a reviewed pull request into protected `main`.

**Goal:** Make the integrated calendar rail customizable without broadening permissions or compromising persistence, accessibility, theme adaptation, or release safety.

**Architecture:** Extend the existing validated settings object with a default 100% control scale, three visibility flags, and a persisted viewport-relative rail position. The toolbar popup writes settings through the existing serialized storage client; the content script reacts to storage changes and owns the temporary move overlay. Dragging uses native Pointer Events with `setPointerCapture`, clamps the rail inside the viewport, and exposes a keyboard/focusable Lock position action. Reset settings writes the complete known default settings but never clears saved checkoffs.

**Tech Stack:** MV3 WebExtension, vanilla DOM/CSS, `chrome.storage.local` through the existing service worker, Node test runner, jsdom, esbuild, local Coloris.
